# Translator Bot - Бот помічник для вивчення слів

## Опис проекту

Telegram-бот створений для зручного вивчення іноземних слів з використанням методики інтервального повторення. Користувачі можуть додавати слова для вивчення, а бот допомагатиме з перекладом, прикладами використання та регулярним нагадуванням про необхідність повторення слів у оптимальні моменти для закріплення знань.

## Функціональні можливості

- **Додавання нових слів**: Користувачі можуть додавати нові слова для вивчення текстом або фотографією.
- **Автоматичний переклад**: Інтеграція з AI-сервісом для автоматичного перекладу та генерації прикладів використання.
- **Повторення слів**: Система інтервального повторення для ефективного запам'ятовування.
- **Відстеження прогресу**: Користувачі можуть переглядати свій прогрес вивчення слів.
- **Медіа-підтримка**: Можливість прикріплювати до слів відео- та фото-приклади для кращого запам'ятовування.
- **Інтервальні нагадування**: Автоматичні нагадування для повторення слів у оптимальний час.

## Технічний стек

- **Backend Framework**: NestJS (Node.js)
- **Мова програмування**: TypeScript
- **База даних**: PostgreSQL з Prisma ORM
- **Кеш**: Redis
- **Управління станом**: Telegram Bot API, власна система стану користувача
- **Планувальник**: NestJS Scheduler
- **AI Services**: Інтеграція з AI для перекладу та генерації прикладів

## Налаштування та запуск

### Вимоги

- Node.js (v14+)
- PostgreSQL
- Redis
- Telegram Bot Token

### Змінні середовища

Створіть файл `.env` у корені проекту з наступними змінними:

```
# Database
DATABASE_URL="postgresql://username:password@localhost:5432/translator_bot?schema=public"

# Telegram
TELEGRAM_BOT_TOKEN=your_telegram_bot_token

# Redis
REDIS_HOST=localhost
REDIS_PORT=6379

# AI Services
AI_SERVICE_API_KEY=your_ai_service_api_key
```

### Встановлення

```bash
# Встановлення залежностей
npm install

# Генерація Prisma клієнта
npx prisma generate

# Міграція бази даних
npx prisma migrate dev
```

### Запуск

```bash
# Розробка
npm run start:dev

# Продакшн
npm run build
npm run start:prod
```

### Запуск з використанням Docker

Проект можна запустити повністю у Docker, включаючи всі компоненти системи моніторингу та логування.

#### Вимоги
- Docker
- Docker Compose

#### Структура Docker Compose

Проект використовує кілька Docker Compose файлів:
- `docker-compose.yml` - основні сервіси (PostgreSQL, Redis, бот)
- `docker-compose.monitoring.yml` - сервіси моніторингу (Prometheus, Grafana)
- `docker-compose.logging.yml` - сервіси логування (ELK Stack)
- `docker-compose.tracing.yml` - сервіси трасування (Jaeger, OpenTelemetry)

#### Кроки для запуску

1. **Створення Docker мережі**:
```bash
docker network create translator-bot-network
```

2. **Налаштування змінних середовища**:
Скопіюйте файл `.env.example` в `.env` та налаштуйте всі необхідні змінні

3. **Запуск основного стеку**:
```bash
docker-compose up -d
```

4. **Запуск системи моніторингу**:
```bash
docker-compose -f docker-compose.monitoring.yml up -d
```

5. **Запуск системи логування**:
```bash
docker-compose -f docker-compose.logging.yml up -d
```

6. **Запуск системи трасування**:
```bash
docker-compose -f docker-compose.tracing.yml up -d
```

7. **Запуск всього стеку одразу**:
```bash
docker-compose -f docker-compose.yml -f docker-compose.monitoring.yml -f docker-compose.logging.yml -f docker-compose.tracing.yml up -d
```

#### Доступ до сервісів

Після запуску, сервіси доступні за наступними адресами:
- **Telegram Bot**: Доступний через Telegram
- **API**: http://localhost:1889/api

- **Prometheus**: http://localhost:9090

## Модулі

### Bot Module

Основний модуль для обробки команд і повідомлень Telegram-бота:

- `/start` - Привітання та початок роботи
- `/mainMenu` - Повернення до головного меню
- `/learnWords` - Додавання нових слів для вивчення
- `/repeatWords` - Початок повторення слів
- `/myProgress` - Перегляд прогресу вивчення

### Word Module

Модуль для роботи зі словами:

- `createWord` - Створення нового слова
- `getWordsByCustomerId` - Отримання слів для конкретного користувача
- `updateWord` - Оновлення слова (наприклад, позначення як вивчене)
- `getLearnedWordsWithPagination` - Отримання вивчених слів з пагінацією

### Message Module

Модуль для формування та відправки повідомлень користувачу:

- `TelegramSendMessage` - Відправка повідомлення через Telegram API
- `fillTemplateAttributes` - Заповнення шаблону повідомлення атрибутами

### Jobs Module

Модуль для планування та виконання завдань:

- `WordRepetitionJob` - Завдання для нагадувань про повторення слів
- `findWordsForRepetition` - Пошук слів, які необхідно повторити
- `sendRepetitionNotification` - Відправка нагадувань про повторення слів

## База даних

Проект використовує PostgreSQL з Prisma ORM. Основні моделі:

### User

Модель для адміністраторів системи.

### Customer

Модель для користувачів Telegram-бота:
- `chatId` - Ідентифікатор чату Telegram
- `state` - Поточний стан користувача (для управління діалогом)
- `words` - Зв'язок з моделлю Word (слова користувача)

### Word

Модель для зберігання слів:
- `word` - Слово для вивчення
- `translation` - Переклад слова
- `examples` - Приклади використання
- `needToLearn` - Чи потрібно ще вчити слово
- `videoExample` - URL відео-прикладу (опціонально)
- `imageExample` - Ідентифікатор фото-прикладу (опціонально)
- `repeatCount` - Кількість повторень
- `lastRepeatAt` - Час останнього повторення
- `nextRepeatDate` - Дата наступного повторення
- `repetitions` - Зв'язок з моделлю WordRepetition

### WordRepetition

Модель для відстеження повторень слів:
- `wordId` - Зв'язок з моделлю Word
- `success` - Успішність повторення
- `intervalNumber` - Номер інтервалу (для розрахунку наступного повторення)

## Робота з повідомленнями

Бот використовує систему шаблонів і атрибутів для гнучкого формування повідомлень:

- `message-templates.json` - Шаблони повідомлень для різних каналів
- `attributes.json` - Атрибути для заповнення шаблонів (підтримує мультимовність)

## Планувальник завдань

Проект використовує `@nestjs/schedule` для планування завдань:

- `WordRepetitionJob` запускається за розкладом для знаходження слів, які потрібно повторити
- Система розраховує оптимальний час для повторення на основі методики інтервального повторення

## Тестування

### Використання тестової сторінки

Проект має вбудовану тестову сторінку для зручного тестування функціоналу бота без використання Telegram. Тестова сторінка розташована за адресою:

```
http://localhost:1889/api/bot-test/test-page
```

Щоб розпочати тестування:

1. **Створення тестового користувача**: Натисніть кнопку "Create Test Customer" для створення користувача з ID чату 123456789.
2. **Тестування команд**: Виберіть команду зі списку або введіть власне повідомлення, а потім натисніть "Test Command".
3. **Перегляд відповіді**: Результат запиту буде відображено в розділі "Response Preview".

Доступні команди для тестування:
- `/start` - Початок роботи з ботом
- `/mainMenu` - Головне меню
- `/learnWords` - Додавання нових слів
- `/repeatWords` - Повторення слів
- `/myProgress` - Перегляд прогресу

## Моніторинг та логування

Проект включає інтегровану систему моніторингу та логування на базі ELK Stack, Prometheus з Grafana та OpenTelemetry.

### OpenTelemetry

Система трасування на базі OpenTelemetry забезпечує:
- Автоматичну інструментацію фреймворків та бібліотек
- Детальне трасування запитів через усі компоненти системи
- Створення та експорт метрик і слідів виконання
- Інтеграцію з Jaeger для візуалізації трейсів

#### Особливості:
- Повний шлях запиту від клієнта до бази даних і назад
- Декоратор `@Trace()` для ручного трасування методів
- Вимірювання часу виконання критичних операцій
- Трасування помилок та винятків
- Інтеграція з AI-сервісами для відстеження часу відповіді

### ELK Stack (Elasticsearch, Logstash, Kibana)

Система централізованого логування забезпечує:
- Збір логів з усіх сервісів через Filebeat
- Аналіз та фільтрацію логів через Logstash
- Зберігання логів у Elasticsearch
- Візуалізацію і пошук в логах через Kibana

#### Особливості:
- Структуровані логи у форматі JSON
- Автоматична агрегація логів за сервісами та рівнями
- Окремий індекс для помилок
- Повнотекстовий пошук та аналітика

### Prometheus і Grafana

Система моніторингу забезпечує:
- Збір метрик продуктивності з усіх сервісів
- Візуалізацію метрик через Grafana
- Налаштовані дашборди для ключових показників
- Можливість встановлення алертів

#### Метрики:
- **HTTP-запити**: кількість, тривалість, статус код
- **Телеграм-повідомлення**: кількість, тип
- **Переклади**: кількість, мова, тип
- **AI-відповіді**: час відповіді, успішність
- **Помилки**: кількість, тип, джерело
- **Кеш**: статистика хітів/промахів, ефективність

### Використання

1. Моніторинг доступний за адресами:
   - Grafana: http://localhost:3000 (логін: admin, пароль: admin)
   - Prometheus: http://localhost:9090
   - Kibana: http://localhost:5601
   - Jaeger: http://localhost:16686

2. Основні дашборди:
   - Application Overview - загальна продуктивність додатку
   - Telegram Bot Metrics - метрики бота
   - Translation Metrics - статистика перекладів
   - Error Tracking - відстеження помилок
   - Cache Performance - продуктивність кешування

### Конфігурація

Налаштування логування, моніторингу та трасування здійснюється через:
- `.env` файл - основні налаштування (LOG_LEVEL, ENABLE_PROMETHEUS, OTEL_*)
- `config/prometheus/prometheus.yml` - конфігурація Prometheus
- `config/logstash/pipeline/logstash.conf` - правила обробки логів
- `config/filebeat/filebeat.yml` - конфігурація збору логів
- `config/otel-collector/config.yaml` - конфігурація OpenTelemetry Collector
